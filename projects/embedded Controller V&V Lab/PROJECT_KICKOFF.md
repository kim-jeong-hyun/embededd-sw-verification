## 1. 학습 범위와 목표
- **핵심:** SWE.6, SYS.4, SYS.5의 목적·대상·기준을 구분하고 해당 수준에 맞는 TC를 직접 설계한다.
- **입력 자료:** SYS.2/3, SWE.1/2의 요구사항·아키텍처·인터페이스 문서는 TC 설계에 필요한 만큼만 읽는다. 별도 문서 작성·리뷰 프로젝트나 필수 선행 단계로 확장하지 않는다.
- **제외:** SWE.4/5 전체. 선택 실습이나 단위·컴포넌트 검증 도구 구축도 이번 범위에 넣지 않는다.
- **집중 활동:** TC 조건 선정, 기법 적용 근거, 재현 가능한 절차, 독립적인 기대 결과, 추적성, 리뷰와 수정.
- **개발 최소화:** 실행·자동화·시뮬레이터 개발은 선택이며 별도 승인 후에만 진행한다. 코드나 실행 결과가 없어도 설계·리뷰 학습을 완료할 수 있다.

## 2. 대상과 입력 자료 관리
전체 프로젝트의 후보 대상은 **차량 보조 전원 및 Wake-up 제어기**다. 시스템 전체 사양이나 기존 Embedded Power Manager(EPM) 문서 재사용은 아직 확정하지 않는다.

첫 과제는 독립된 교육용 SW 요구사항으로 범위를 제한한다. 아래 수치·신호는 이 과제의 입력이며 실제 제품이나 기존 EPM의 승인 사양이 아니다. 기존 문서를 사용하려면 출처·버전·적용 범위를 확인한다. 시스템 구성요소와 인터페이스는 해당 단계로 이동 승인받은 뒤 필요한 만큼 제공한다.

## 3. 학습 단계와 승인 절차
| 단계 | 핵심 영역 | 학습자가 직접 수행할 일 | 최소 산출물 | 완료 기준 |
|---|---|---|---|---|
| 1 | SWE.6 | SW 요구사항 기반 TC 작성, 설계 근거 설명, 리뷰 반영 | `03_test_design/SWE6_TC.md`, 관련 리뷰 기록 | 추적성, 재현성, 판정 가능성 확인 및 지적사항 처리 |
| 2 | SYS.4 | 구성요소 간 인터페이스·상호작용 검증 TC 작성 및 수정 | `03_test_design/SYS4_TC.md`, 관련 리뷰 기록 | 통합 범위·관찰 지점·기준 문서와 기대 결과의 일치 |
| 3 | SYS.5 | 시스템 요구사항 기반 TC 작성 및 수정 | `03_test_design/SYS5_TC.md`, 관련 리뷰 기록 | 시스템 경계에서 요구 충족 여부를 판정할 수 있는 TC와 추적성 |

이는 학습 순서이며 ASPICE 활동의 의무적인 수행 순서를 뜻하지 않는다. 각 단계는 작은 과제로 나누고 **과제 제시 → 학습자 작성 → Codex 리뷰 → 학습자 수정 → 재리뷰**로 진행한다. 첫 과제 완료만으로 SWE.6 전체가 완료된 것으로 간주하지 않는다.

현재 과제 또는 단계가 끝나면 완료 여부와 미해결 사항을 요약하고 다음 과제·단계 이동 승인을 기다린다. 명시적인 승인 없이 다음 과제 입력 제공, 단계 이동, 실행·개발에 착수하지 않는다. 제출이나 리뷰 요청은 이동 승인이 아니다.

Codex는 검증 수준, 추적성, 조건 선정과 기법의 근거, 사전 조건·절차의 재현성, 기대 결과의 출처와 판정 가능성, 누락·중복, 우선순위를 검토한다. 완성 TC를 대신 작성하지 않고 학습자가 수정할 수 있는 피드백을 제공한다.

리뷰 상태는 초안/리뷰 중/수정 필요/승인, 실행 판정은 Not Run/Pass/Fail/Blocked로 구분한다. 현재 설계 실습의 실행 판정은 **Not Run**이다.

## 6. 첫 번째 SWE.6 학습 과제 — IGN 기반 전원 요청
### 6.1 목표와 대상 경계
통합된 제어기 SW의 외부 입출력을 기준으로 SW 요구사항을 검증하는 TC를 직접 작성한다. 코드·내부 함수·실제 릴레이 동작은 검증 대상이 아니다. 이번에는 TC 설계와 리뷰만 수행한다.

### 6.2 교육용 입력: SW-INPUT-001 v1.0
별도 요구사항 문서: [SWE6_IGN_Requirements.md](01_requirements/SWE6_IGN_Requirements.md). 아래 내용과 동일한 v1.0 입력이며, 이후 입력 변경 시 두 문서의 일치 여부를 확인한다.

상태는 **첫 과제용 고정 입력 / 제품 기준선 아님**이다.

- 대상 SW는 전원이 공급되고 초기화가 완료된 상태다. 고장·다른 전원 제어 요청·출력 억제 조건은 없다.
- 입력 `IGN`은 SW 외부 입력 지점에서 관찰되는 유효한 Boolean 신호다. ON과 OFF만 다룬다. 물리 신호의 노이즈·디바운싱·통신 지연은 범위 밖이다.
- 출력 `PWR_REQ`는 SW 외부 출력 지점의 Boolean 전원 요청이다. ENABLE과 DISABLE을 사용한다. 실제 장치 전원은 관찰 대상이 아니다.
- `t0`는 SW 입력 지점에서 IGN 변경이 관찰된 시각이다. 시험 환경은 입력을 설정하고 출력 및 시간을 1 ms 단위로 관찰할 수 있다고 가정한다. 실제 환경을 구축하거나 실행한 상태는 아니다.

| SW 요구사항 ID | 요구사항 |
|---|---|
| SWR-IGN-001 | IGN이 OFF에서 ON으로 변경되고 ON으로 유지되면, SW는 t0부터 100 ms 이내(100 ms 포함)에 PWR_REQ를 ENABLE로 설정하고 IGN이 ON인 동안 유지해야 한다. |
| SWR-IGN-002 | IGN이 ON에서 OFF로 변경되고 OFF로 유지되면, SW는 t0부터 100 ms 이내(100 ms 포함)에 PWR_REQ를 DISABLE로 설정하고 IGN이 OFF인 동안 유지해야 한다. |

다음 IGN 변경이 100 ms 응답 구간 안에 발생하는 상황, 초기화 중 동작, 고장 처리는 이번 과제에서 제외한다. 유지 동작의 관찰 구간은 학습자가 정하고 선정 근거를 설명한다. 유한한 관찰 구간으로 보장할 수 있는 범위도 구분한다.

### 6.3 학습자 제출물
작성 파일: [SWE6_TC.md](03_test_design/SWE6_TC.md). 복사해서 사용할 수 있는 빈 TC별 양식이며 정답은 포함하지 않는다.

1. 두 요구사항을 대상으로 **TC 3~5개**를 빈 양식에 직접 작성한다. 개수는 학습 분량이며 충분한 커버리지를 자동으로 뜻하지 않는다.
2. 검증 수준은 SWE.6로 표시하고 기준 문서 버전과 요구사항 ID를 연결한다.
3. 조건 선정 이유와 적용 기법, 관찰 시간 및 Pass/Fail 판단 기준을 직접 설명한다.
4. 입력이 불명확하다고 판단되면 임의로 보완하지 말고 질의와 설계 영향을 함께 제출한다.
5. 대화에 Markdown 표로 제출하거나 `03_test_design/SWE6_TC.md`에 직접 작성한다. 리뷰 상태는 초안, 실행 판정은 Not Run으로 둔다.

### 6.4 완료 기준과 정지 지점
두 요구사항의 추적성, 절차의 재현성, 시간·유지 조건의 판정 가능성, 설계 근거를 리뷰하고 지적사항 처리 상태를 확인한다. TC 정답이나 예시 TC는 미리 제공하지 않는다. **현재는 학습자의 TC 제출을 기다리며 다음 과제로 넘어가지 않는다.**

## 7. 선택 활동과 전체 완료 기준
도구 설치, 자동화, 시뮬레이터 구현, 테스트 실행, 변경 영향·회귀 분석은 별도 승인 후 선택적으로 수행한다. 이 활동을 수행하지 않아도 아래 필수 기준을 충족하면 프로젝트를 완료할 수 있다.

- SWE.6, SYS.4, SYS.5 각각 학습자가 직접 작성하고 리뷰·수정한 대표 TC 세트가 있다.
- 각 TC에 검증 수준, 기준 문서와의 추적성, 재현 가능한 절차, 관찰 가능한 기대 결과와 설계 근거가 있다.
- 리뷰 지적사항의 해결 여부와 수용 근거가 기록되고 미해결 질의 및 검증 한계가 구분되어 있다.
- 학습자가 수준별 TC 차이와 조건 선정 이유를 스스로 설명할 수 있다.
- 각 단계 이동과 최종 완료에 대한 학습자의 명시적인 승인이 있다.
